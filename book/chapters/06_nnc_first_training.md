# 第6章 Neural Network Console ではじめての学習 — 9割当てる AI を1分半で

前章までで、ニューラルネットワークの仕組み（頭）と NNC の画面（道具）がそろいました。この章ではいよいよ学習を実行します。方針は「まず動かして成功体験、それから中身を読み解く」。章が終わるころには、**10種類の衣類画像を9割の精度で見分ける AI を自分の手で作り、その成績表まで読める**ようになっています。

題材は NNC 付属の **LeNet サンプル**です。データセットは **Fashion-MNIST** — T シャツ、ズボン、スニーカー、バッグといった衣類・小物の白黒写真（28×28）が7万枚詰まった、機械学習の定番教材です。手書き数字ではなく「モノの写真」なのがポイントで、第7章から作る「自分のカメラで撮ったモノの分類」への、ちょうどよい足がかりになります。

## 6.1 LeNet サンプル（Fashion-MNIST）を開いて動かす — まず成功体験

### プロジェクトを開く前に — エンジンは「(nnabla)」

NNC を起動し、ホーム画面のプロジェクト一覧から `LeNet.sdcproj` を探してダブルクリックします。初回はデータセット（Fashion-MNIST）のダウンロード確認が出るので、了承して少し待ちます。

<!-- 図版: book/figures/nnc/02_nnc_sample_project_list.png (プロジェクト一覧) -->

ここで、先々のために大事な注意をひとつ。ホーム画面の上部に「新しいプロジェクト **(nnabla)**」「新しいプロジェクト **(Torch)**」など、**エンジン違いの新規作成ボタンが複数並んでいます**。本書で自分のプロジェクトを作るときは、**必ず (nnabla) を選んでください**。第8章で使うマイコン向け変換（.nnb 形式）は nnabla 形式のモデルを前提にしているためです。LeNet サンプルは nnabla 製なのでそのまま使えます（開いたウィンドウのタイトルバーに `(NNabla)` と表示されていることを確認してください）。

### 設計図を眺める — 第5章の答え合わせ

プロジェクトが開くと「編集」タブに LeNet の設計図が現れます。上から順に読んでみましょう — 第5章で学んだ部品が、ほぼそのまま並んでいます。

<!-- 図版: book/figures/nnc/03_nnc_lenet_edit_page.png (編集タブ・LeNet全景) -->

```text
  Input (1,28,28)        ← 28×28・1チャンネルの画像が入口
  Convolution 7×7  → (16,22,22)   ← 判子16種で捜査開始
  ReLU
  MaxPooling 2×2   → (16,11,11)   ← 縮めて鈍感に
  Convolution_2 3×3 → (30,9,9)    ← 2巡目の捜査は判子30種
  MaxPooling_2 2×2 → (30,4,4)
  Tanh_2                  ← 新顔! (後述)
  Affine → (150)          ← 全証拠を150人の陪審員へ
  ReLU_2
  Affine_2 → (10)         ← 評決は10クラス
  Softmax                 ← 点数を確率に
  CategoricalCrossEntropy ← 採点係(学習専用)
```

各ブロックの右に添えられた `16,22,22` のような数字は、**そこを通過した時点のデータの形**です。28×28 の画像が、捜査と縮小を経て 4×4×30 の「証拠の束」になり、最後は10個の確率になる — データの旅路が数字で追えます。

ひとつだけ第5章に出てこなかった顔がいます。**Tanh（タンエイチ）**は ReLU のご先祖にあたる活性化関数です。LeNet は1998年生まれの由緒正しいネットワークで、当時は Tanh が主流でした。役割は ReLU と同じ「味付け」なので、身構える必要はありません。歴史的建造物の意匠だと思って眺めてください。

もうひとつ、画面右の**統計情報**に目をやると `CostParameter 78,810` とあります。このネットワークのダイヤル（重み）は約7.9万個 — メモリにすると約300KB です。「あれ、第1章の 14KB より大きい」と気づいた人は鋭い。そう、**LeNet はこのままでは Pico に載せるには重い**のです。ダイヤルを削って 14KB 級にする技は第8章のお楽しみです。

### データセットを確認する

右上の**データセット**ボタンを押すと、教材の中身が見えます。

<!-- 図版: book/figures/nnc/08_nnc_dataset_page.png (データセットタブ) -->

- Training: `fashion_mnist_training.csv` — **60,000枚**（学習用の例題）
- Validation: `fashion_mnist_test.csv` — **10,000枚**（初見の実力テスト用）
- 画像をクリックすると、アンクルブーツや T シャツのざらついた 28×28 画像が確認できます

地味に重要なのが、上部の **「Image Normalization (1.0/255.0)」** のチェックです。これは「画素値 0〜255 を 255 で割って 0.0〜1.0 に直してから入力する」という前処理の宣言で、**第9章で Pico 側の前処理をこれとぴったり揃える**ことになります。学習時と推論時で前処理が食い違うと精度は崩壊します。伏線として覚えておいてください。

### 実行 — 1分半の見守り

編集タブに戻り、右上の**実行**ボタンを押します。画面が自動的に「学習」タブへ切り替わり、学習曲線がじわじわと伸びはじめます。60,000枚 × 10周（エポック）の学習で、所要は筆者環境で**約1分半**でした。コーヒーを淹れる間もありません。

ログ窓に `Training Completed.` が出たら学習完了です。続けて右上の（今度は「評価」の）**実行**を押すと、10,000枚の実力テストが走ります。こちらは十数秒。終わると評価タブに1枚ごとの判定結果がずらりと並びます。

<!-- 図版: book/figures/nnc/06_nnc_eval_accu_page.png (評価タブ・出力結果) -->

「混同行列」のラジオボタンに切り替えて、左上の **Accuracy** を見てください。筆者の実行では **0.9016** — 初見の1万枚に対して**正解率 90.2%** です。

おめでとうございます。ドラッグもドロップもまだ何もしていないのに、あなたはいま、衣類を9割見分ける AI をこの手で学習させました。ここからは、この結果を「読める」ようになりましょう。

## 6.2 学習曲線と混同行列を読む — 数字の向こうの「モデルの気持ち」

### 学習曲線 — 3本の線が語ること

学習タブのグラフには3本の線があります。

<!-- 図版: book/figures/nnc/05_nnc_train_page.png (学習タブ・学習曲線) -->

- **COST**：採点係（CategoricalCrossEntropy）がつけた「間違いの大きさ」。学習が進むほど下がる
- **TRAINING ERROR**：学習に使った例題での誤答率
- **VALIDATION ERROR**：初見データでの誤答率 — **本当の実力はこちら**

筆者の結果は、10エポック終了時点で TRAINING ERROR が **0.166**、VALIDATION ERROR が **0.280** でした。この**2本の開き**こそ、第5章で予告した**過学習**のサインです。例題の丸暗記が進むと、TRAINING ERROR だけが下がり続け、初見の VALIDATION ERROR は下げ止まり、やがて悪化に転じます。

- 2本が仲良く下がっている → 健全。もう少し学習を続けてもよい
- TRAINING だけ下がり、VALIDATION が横ばい・上昇 → 丸暗記が始まった。**これ以上回しても実力は伸びない**

NNC には保険が用意されています。コンフィグの**「最良のモデルを保存」**にチェックが入っていると、全エポック中で VALIDATION が最も良かった瞬間のモデルが自動的に残ります。回しすぎても最良点は失われない、ありがたい仕組みです。

なお、学習結果リストに **PARETO OPTIMAL** というバッジが付いていますが、これは 6.4 の構造自動探索で意味を持つ表示です。今は「精度と計算量のバランスがよい印」程度に流してください。

### 混同行列 — 間違いの「地図」

混同行列は、**行が正解、列がモデルの答え**の集計表です。対角線上（正解＝答え）に数字が集まっているほど優秀で、対角線から外れた数字は「取り違え」の記録です。

<!-- 図版: book/figures/nnc/07_nnc_eval_conf_matrix_page.png (評価タブ・混同行列) -->

筆者の結果から、クラスごとの Precision（そのクラスと答えたときの的中率）を拾うと：

| クラス | Precision | 読み解き |
|---|---|---|
| Trouser（ズボン） | **0.9989** | ほぼ完璧。縦長のシルエットは唯一無二 |
| Dress（ワンピース） | 0.9116 | 良好 |
| T-shirt/top | 0.8508 | ときどき迷う |
| Pullover（セーター） | 0.8127 | 迷いがち |
| Coat（コート） | 0.8090 | 迷いがち |

パターンが見えるでしょうか。**上半身に着る服同士（Tシャツ・セーター・コート・シャツ）で取り違えが集中**しています。28×28 の白黒シルエットでは、袖のある上衣はどれも似た形 — 人間が同じ条件で見ても迷うはずのペアで、モデルも迷っているのです。

ここから、本書全体で使う大事な教訓を引き出せます。

> **モデルの間違い方は、人間の間違い方に似る。**
> 見た目がそっくりなクラス同士は、AI にとっても難問である。

第7章で自分のカメラの題材（クラス）を決めるとき、この教訓が効いてきます。「置き配がある/ない」のようにシルエットがはっきり違う2クラスは易しく、「宅配便の箱/ポリ袋の荷物」のような見分けは難しい。**題材選びの段階で、混同行列の苦労を減らせる**のです。

## 6.3 ドラッグ&ドロップで自分のネットワークを組む

### 空のキャンバスから

借り物の LeNet を動かせたので、今度は自分の手で組みます。ホーム画面に戻り、**「新しいプロジェクト (nnabla)」**（← 念押しです）をクリック。空のキャンバスが開いたら、左の**コンポーネント**棚から部品をドラッグして、第5章の定番構成を小ぶりに組んでみましょう。

```text
  Input → Convolution → ReLU → MaxPooling
        → Convolution_2 → ReLU_2 → MaxPooling_2
        → Affine → ReLU_3 → Affine_2 → Softmax → CategoricalCrossEntropy
```

部品を縦に並べると、上下のブロックは自動的に接続されます（つながらないときは、ブロック下端の黒点を次のブロックへドラッグ）。それぞれのブロックをクリックし、左下の**レイヤープロパティ**で設定を入れます。

| ブロック | プロパティ | 値 | 意味 |
|---|---|---|---|
| Input | Size | `1,28,28` | 白黒 28×28 |
| Convolution | OutMaps / KernelShape | `8` / `3,3` | 判子8種・3×3（LeNet の半分以下） |
| Convolution_2 | OutMaps / KernelShape | `16` / `3,3` | 判子16種 |
| Affine | OutShape | `32` | 陪審員32人（LeNet は150人） |
| Affine_2 | OutShape | `10` | 10クラスぶんの評決 |

わざと LeNet より小さく設計しているのは、第8章「モデルをマイコンサイズにする」の頭出しです。組み終わったら統計情報の **CostParameter** を見てください — LeNet の数分の一になっているはずです。

### データセットの割り当てと学習設定

- **データセット**ボタン → 「アクション」からデータセットを開き、LeNet サンプルと同じ `fashion_mnist_training.csv` / `fashion_mnist_test.csv` を Training / Validation に割り当てます（一度サンプルを動かしていれば一覧から選ぶだけです）
- **コンフィグ**ボタン → 学習反復世代数（Max Epoch）`10`、バッチサイズ `64`、「最良のモデルを保存」にチェック

<!-- 図版: book/figures/nnc/04_nnc_configt_page.png (コンフィグ画面) -->

あとは**実行**。学習曲線を眺め、評価を回し、混同行列を読む — 6.1〜6.2 でやった一巡を、今度は**自分が設計したモデル**で繰り返してください。精度はおそらく LeNet より数ポイント下がりますが、パラメータ数は激減しているはずです。「精度を何ポイント差し出せば、モデルを何分の一にできるか」— このトレードオフの感覚こそ、エッジAI設計者の商売道具です。

うまく動かないときの定番は3つ：Input の Size が `1,28,28` になっていない／最後の採点係（CategoricalCrossEntropy）を置き忘れた／データセットの割り当て忘れ。エラーメッセージより先に、この3点を確認すると早いです。

## 6.4 構造自動探索（Structure Search）の紹介

コンフィグ画面に**「構造自動探索」**という項目があったのに気づいたでしょうか。これは NNC の名物機能で、有効にして学習を回し続けると、**NNC がネットワーク構造を自動で組み替えながら、より良い構造を探し続けてくれます**。

面白いのは最適化の物差しです。「最適化対象：Error and Calculation」— つまり**誤差と計算量の両方**を小さくしようとします。探索を続けると、学習結果リストに「これ以上、精度を落とさず軽くできない（軽くせずに精度を上げられない）」という均衡点のモデルたちが **PARETO OPTIMAL** のバッジ付きで並んでいきます。6.2 で見たあのバッジの正体です。

「小さくて、当たる」を機械に探させる — マイコン向けモデル作りと相性抜群の機能で、実際、第8章で行う手作業のダイエットの強力な代替になります。ただし探索には時間がかかります（数時間〜一晩）。本書の本編は見通しのよい手設計で進み、構造自動探索は「PC を寝かせておく夜の自由研究」としておすすめしておきます。
