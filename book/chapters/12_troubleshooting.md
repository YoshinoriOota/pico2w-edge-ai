# 第12章 トラブルシューティングと次の一歩 — 転び方の地図と、その先の道

最終章は2部構成です。前半は、本書の旅で出会う（そして筆者が実際に転んだ）トラブルを一枚の地図にまとめます。各章に散らばった「診察室」の総索引です。後半は、この本を出たあなたが次に歩ける道を示します。

## 12.1 よくあるハマりどころ集 — 症状から引く総索引

デバッグの鉄則から始めます。**エラーメッセージが出るトラブルは、実は簡単なトラブルです。** 本当に手強いのは「エラーなく、静かに、間違い続ける」やつです — PIO は無言で待ち続け、パケットは無言で消え、精度は無言で崩れます。だからこの索引は「何が表示されたか」ではなく「**何が起きて見えるか**」で引けるように作りました。

## 12.2 精度が出ないときの切り分けフロー — データ→前処理→モデルの順に疑う

### 疑う順番を間違えると迷宮入りする

「実機で精度が出ない」とき、初心者は決まってモデルをいじり始めます — 層を増やし、フィルタを増やし、エポックを増やし…そして状況はたいてい悪化します。**モデルは容疑者リストの最後**です。捜査は必ずこの順で：

```text
 【Q1】NNC の評価タブで精度は出ているか?
   │
   ├─ No → 犯人は「データ」。モデルをいじっても無駄
   │        ├ 枚数不足 (各クラス100枚未満なら、まず撮る)          → 7.4
   │        ├ クラスが紛らわしい (混同行列で確認。題材を再考)       → 6.2, 7.2
   │        └ ラベル間違い (数枚混ざるだけで効く。サムネイル総点検)
   │
   └─ Yes → 【Q2】9.5 の数値一致テストは通るか?
              (NNC評価の1枚をPicoに入れ、出力値を突き合わせる)
       │
       ├─ No → 犯人は「前処理」。ほぼ100%ここ
       │        ├ ÷255 の正規化を忘れた/二重にかけた              → 9.3
       │        ├ 切り出し位置・間引きが収集ツールとずれた          → 7.1
       │        └ クラス番号とフォルダ名の対応がずれた             → 7.3
       │
       └─ Yes → 犯人は「学習時と本番の世界の違い」
                 ├ カメラの位置・画角が収集時から動いた (最多!)     → 7.4
                 ├ 照明・時間帯が学習データに無いパターン           → 7.4
                 └ 対策はひとつ: 本番の「その環境」で撮り足して再学習 → 11.4
```

### このフローが強力な理由

各分岐に**実験で白黒つけられる検問**があるからです。Q1 は NNC の画面を見るだけ。Q2 は第9章で儀式化した数値一致テスト。どちらも数分で終わり、答えは Yes/No で出ます。「なんとなくモデルが悪い気がする」という霧の中の勘は、もう要りません。

とくに Q2 の切れ味は覚えておいてください。**7桁一致すればランタイムとモデルは完全に無実**（第9章で証明済み）。一致しなければ前処理 — 容疑者が一気に数人まで絞れます。そして最終分岐で行き着く「本番環境で撮り足して再学習」は、敗北ではなく**エッジAI の正規の運用**です（11.4 の育てるループ）。精度は一度作るものではなく、環境と一緒に育てるもの — 本書の締めくくりにいちばん伝えたい感覚です。

## 12.3 次の一歩 — この本を出たあとの3つの道

置き配カメラが玄関で動き始めたら、この本の役目は終わりです。最後に、その先に伸びる道を3本だけ示します。

### 道1：nnabla（Python 版）へ — GUI の卒業

NNC の中身は、Sony のオープンソースライブラリ **nnabla（Neural Network Libraries）**です。Python で `pip install nnabla` すれば、本書で GUI でやってきたこと — ネットワーク定義、学習、.nnb 変換（`nnabla_cli` コマンド）— がすべてコードで書けます。

GUI からの卒業が意味を持つのは「**自動化したくなったとき**」です。11.4 の育てるループを何十周も回すなら、収集→学習→変換→転送をスクリプト1本にしたくなる。NNC のプロジェクト（.sdcproj や .nnp）は nnabla からも読めるので、これまでの資産を持ったまま移行できます。Mac/Linux だけで完結できるようになるのも、人によっては大きな解放です。

### 道2：ファームウェアの中へ — C の世界の入口

本書は「C を書かない」を貫きましたが、あなたの Pico の中では、Sony の nnabla-c-runtime という C 実装が働いていました。付録 F の手順で**自分でファームウェアをビルド**してみると、この層に手が届くようになります。

見返りは自由です。dnnrt モジュールの改造、前処理の C 化（viper のさらに先）、対応レイヤーの追加移植 — MicroPython の快適さと C の力を「usermod」という形で橋渡しする技術は、あらゆるマイコン開発に応用が利きます。急ぐ道ではありませんが、いつか「ランタイムの中を見たい」と思った日のために、扉の場所だけ覚えておいてください。

### 道3：より広いエッジAIへ — 装備を替えて登る山

第8章のエクスポートメニューに ONNX や tflite が並んでいたのを覚えていますか。あれは「NNC で学習したモデルは、**別の推論エンジンにも旅立てる**」という意味です。TensorFlow Lite for Microcontrollers（TFLite Micro）は本書と同じ Pico でも動く別峰で、対応レイヤーやツールの生態系が異なります。本書の知識 — 前処理の一致、メモリの家計簿、数値突き合わせ — は、エンジンが変わってもそのまま通用します。

ボードを替える道もあります。Sony **SPRESENSE** は DNNRT の本家で、カメラも GPS も揃った上位機です。さらに上には Raspberry Pi Zero のような Linux ボード、物体検出（どこに何があるか）のような重いタスクの世界が続きます。ただ、登る前に思い出してください — 本書のカメラは、520KB と 14KB でちゃんと仕事をしました。**大きな装備が必要かどうかは、問題が決めることであって、流行が決めることではありません。** それを見抜く目こそ、この本であなたが手に入れた一番の装備です。

### 結びに — 小さな機械に、考えることを教えた

最後まで読んでくださって、ありがとうございました。

振り返れば、ずいぶん遠くまで来ました。ジャンパワイヤ18本の配線から始まり、PIO のアセンブリを書き、自分の玄関のデータセットを作り、ニューラルネットワークを学習させ、310KB を 14KB に絞り、PC とマイコンで7桁一致する推論を確かめ、29mA の罠を避けて6mA の眠りを手に入れ、電池だけで2週間働く装置を玄関に置いた — 全部、あなたの手でやったことです。

エッジAI は、巨大なデータセンターの AI と比べれば、豆粒のような存在です。でも、電源もネットワークも人の目も届かない場所で、電池2本で黙々と役目を果たす豆粒には、独特の誠実さがあります。作った人にしかわからない愛着と言ってもいい。あなたの玄関のカメラが今夜も静かに起きて、撮って、考えて、眠る — その10分ごとの営みを、どうか時々思い出してやってください。

次の豆粒に、何を考えさせましょうか。
