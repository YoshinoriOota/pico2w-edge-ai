# 第5章 ニューラルネットワークの基礎 — 「見て、判断する」の中身

前章で Pico は目を手に入れました。この章では、撮った画像を「わかる」に変える仕組み — ニューラルネットワークの中身を学びます。ハンダごてもジャンパワイヤも登場しません。かわりに、この章を終えたとき、あなたは次章で NNC のキャンバスに置くブロックひとつひとつの意味がわかるようになっています。

先に約束をひとつ。**数式は最小限、登場するのは足し算と掛け算だけ**です。ニューラルネットワークは「積和演算の集合体」であり、高校数学で全体像をつかめます。魔法のように見えるものを、使いこなせる道具に変える — それがこの章の仕事です。

## 5.1 ニューロン、層、重み — 数式最小限で仕組みを理解する

### 「判断」を数値の変換として捉え直す

私たちが作りたいのは「玄関先の画像を見て、荷物があるか判断する」装置でした。この仕事を、機械に扱える形に言い換えます。

- **入力**：28×28 = 784 個の数値（各画素の明るさ。0.0〜1.0）
- **出力**：2 個の数値（「荷物あり」らしさ、「荷物なし」らしさ）

つまり判断とは、**784 個の数値を 2 個の数値に変換すること**です。ニューラルネットワークは、この変換を行う計算の仕掛けにすぎません。まずは変換の最小部品から見ていきます。

### 最小部品：ニューロンは「重み付き投票」

ニューロン1個の仕事は、こう書けます。

```text
  出力 = (入力1 × 重み1) + (入力2 × 重み2) + … + (入力784 × 重み784) + 下駄
```

全入力に「重み」を掛けて足し合わせ、最後に「下駄」（バイアス）を履かせる。それだけです。イメージは**重み付き投票**です。玄関の床のあたりの画素には大きな重み（荷物の有無がよく現れる場所だから）、空が写る上端の画素にはほぼゼロの重み（関係ないから）。全画素の「一票」を、重要度をつけて集計するわけです。

集計のあと、小さな仕上げが入ります。**ReLU（レル）**という関数で、「集計結果がマイナスなら 0 に切り上げる」— つまり**マイナスの意見は黙らせる**のです。

```text
  ReLU:  集計が +3.2 → そのまま 3.2 を次へ
         集計が -1.7 → 0 を次へ(発言権なし)
```

なぜこんな一手間を入れるのか。もし入れないと、どれだけ層を重ねても全体がただの巨大な足し算に潰れてしまい、複雑な判断が作れないからです。理屈は深追いしなくて構いません。「**ReLU は料理の塩。入れないと層を重ねる意味が消える**」とだけ覚えてください。

### 部品を並べ、重ねる — 層とネットワーク

ニューロン1個は一種類の集計しかできませんが、**違う重みを持ったニューロンを何十個も並べる**と、それぞれが画像の違う側面に注目する集計者になります。この並びが**層**です。さらに、層の出力を次の層の入力につなぐと：

```text
   784画素 ──→ [第1層: 32人の集計者] ──→ [第2層: 16人] ──→ [出力層: 2人]
                「明暗の境目がある?」      「箱っぽい形?」     「荷物あり/なし」
                 単純な特徴を拾う          特徴を組み合わせる    最終判定
```

前の層が拾った単純な特徴（線、角、明暗）を、次の層が組み合わせてより複雑な特徴（縁、面、形）に育てる。**単純な質問の積み重ねが、複雑な判断になる** — これがニューラルネットワークの核心のアイデアで、「ディープ（深層）」とは単に層が多いことを指しています。

### では「重み」は誰が決めるのか

ここまでで、勘のいい読者は気づいたはずです。この仕掛けの賢さは、すべて**重みの値**に握られている、と。その通りです。ニューラルネットワークの設計図（層の数や並べ方）はただの器で、器に注がれた何千・何万個の重みの値こそが「能力」の実体です。

そして重みは、人間が決めません。**データから自動的に決めます** — それが「学習」で、5.3 で扱います。ちなみに第1章で予告した「14KB のモデル」の中身は、ほぼこの重みの数値の羅列です。14KB ÷ 4バイト ≒ 3,500個のダイヤルが、あなたの玄関先仕様に調整されて詰まっている — そういうファイルです。

## 5.2 画像認識に効く CNN（畳み込み）の直感的理解

### 全画素投票の弱点

5.1 の「784画素の重み付き投票」（この方式を**全結合**、NNC 用語では **Affine** と呼びます）には、画像に対する致命的な弱点があります。**位置に弱い**のです。

荷物が画面の左に写ったときと右に写ったときでは、値の入る画素がまったく別ですから、全結合にとっては別問題になってしまいます。左の荷物で学習しても右の荷物がわからない。荷物は毎回同じ場所には置かれないのに、です。

### 判子を滑らせる — 畳み込み

そこで登場するのが**畳み込み（Convolution）**です。発想の転換はこうです。

> 画像全体を一度に見るのをやめて、**小さなパターン検出器（3×3画素ほど）を作り、画像の全域に滑らせながら押していく**

この小さな検出器を**フィルタ**と呼びます。たとえば「縦の明暗境界に反応する」フィルタを画像全体に滑らせると、「画像のどこに縦エッジがあったか」を示す新しいマップ（**特徴マップ**）が出来上がります。

```text
   入力画像(28×28)          フィルタ(3×3)         特徴マップ(縦エッジの地図)
   ┌────────────┐          ┌───┐               ┌────────────┐
   │  ▐▌        │          │-1 0 +1│  滑らせる   │  ██        │
   │  ▐▌  ▄▄▄   │  ×      │-1 0 +1│  ────→    │  ██  ▖▖    │
   │  ▐▌  ███   │          │-1 0 +1│           │  ██  ▌▌    │
   └────────────┘          └───┘               └────────────┘
    どこに何がある           このパターンを探せ      「ここにあった」の地図
```

大事な性質が2つあります。

**第一に、位置に強い。** 同じ判子を全域に押すので、荷物が左にあろうと右にあろうと、同じフィルタが同じように反応します。「何が」と「どこに」を分けて扱えるのです。

**第二に、驚くほど倹約。** フィルタ1枚の重みは 3×3 = 9個だけ。全域で使い回す（**重み共有**）ので、784個の重みを画素ごとに持つ全結合とは桁違いに小さい。**マイコンに載る 14KB という小ささは、畳み込みの倹約のおかげ**です。

実際の畳み込み層は、フィルタを16枚、32枚と束で持ちます。1枚目は縦エッジ、2枚目は横エッジ、3枚目は斜め… どんなパターンを探すべきかは、これも学習が勝手に決めます。

### MaxPooling — 縮めて、鈍感にする

畳み込みとセットで使われるのが **MaxPooling（マックスプーリング）**です。仕事は単純で、特徴マップを 2×2 の区画に切り、**各区画の最大値だけ残して4分の1に縮小**します。

```text
   ┌────┬────┐
   │ 0.1  0.8 │ 0.2  0.0│         ┌─────┬─────┐
   ├────┼────┤   ──→   │ 0.8  │ 0.2  │   「左上のどこかに
   │ 0.3  0.2 │ 0.1  0.1│         └─────┴─────┘    強い反応があった」
   └────┴────┘
```

情報を捨てているように見えますが、これが良い仕事をします。「エッジが (3,7) にある」を「エッジが左上あたりにある」へと**わざと曖昧に**することで、数画素のずれ、傾き、ノイズに動じなくなるのです。ついでにデータが縮むので、後段の計算とメモリも軽くなる。マイコンにとっては一石二鳥の部品です。

### 定番の組み立て — 本書モデルの原型

部品が出そろいました。画像認識ネットワークの定番構成は、こうなります。

```text
  入力(1×28×28)
    ↓ Convolution ……… 単純なパターンの地図を作る(フィルタ16枚)
    ↓ ReLU        ……… マイナスは黙らせる
    ↓ MaxPooling  ……… 縮めて鈍感に(14×14へ)
    ↓ Convolution ……… 地図の組み合わせでより複雑なパターンを拾う(32枚)
    ↓ ReLU
    ↓ MaxPooling  ……… さらに縮める(7×7へ)
    ↓ Affine      ……… ここで初めて全結合: 全証拠を集めて総合判定
    ↓ Softmax     ……… 判定を「確率」に変換
  出力(クラスごとの確率)
```

前半（Conv/Pool の繰り返し）が**証拠集めの現場捜査**、最後の Affine が**全証拠を並べて評決する裁判所**、という分担です。

最後の **Softmax（ソフトマックス）**だけ補足します。Affine の出力は「荷物あり: 8.2点、なし: 1.3点」のような生の点数で、そのままでは扱いにくい。Softmax はこれを**合計が 1.0 になる確率**に変換します（8.2点 → 99.9%、のように）。第9章で Pico が出してくる「class 9、確率 0.9999」という答えの正体が、まさにこの Softmax の出力です。

## 5.3 学習と推論の違い — 学習は NNC、推論は Pico

### 推論：ダイヤルを固定して流すだけ

**推論**とは、学習済みの（＝重みが決まった）ネットワークに入力を流し、出力を得ることです。中身は掛けて、足して、ReLU で切って…の一本道。分岐も試行錯誤もない、ただの計算の流れ作業です。

だからこそ**マイコンでもできます**。第2章で Pico に入れた DNNRT の仕事は、この流れ作業を C の速度で回すことだけ。784回の入力に対し数万回の積和演算をこなして、実測 90ms — 流れ作業なら RP2350 でも余裕なのです。

### 学習：間違えては、ダイヤルを回す

一方の**学習**は、重みの値そのものを決める工程です。仕組みを一言でいえば「**間違いから逆算してダイヤルを回す**」の繰り返しです。

```text
  ① 例題を1枚見せる         「この画像は?」
  ② いまの重みで推論させる    「荷物あり…かな(60%)」
  ③ 正解と比べる            正解は「なし」。60%も間違えた
  ④ 間違いの責任を各重みに配分  「お前が+に押しすぎた」「お前は無罪」
  ⑤ 責任に応じてダイヤルを微調整
  ⑥ ①へ戻る — これを数千枚 × 何十周
```

④の「責任の配分」を数学的にやる仕組みが誤差逆伝播（バックプロパゲーション）ですが、本書では名前だけで十分です。NNC の学習実行ボタンの裏で回っているのはこのループだ、とわかっていれば使いこなせます。

### なぜ学習は PC で、推論は Pico なのか

学習と推論の正体が見えると、本書のワークフローの必然性もはっきりします。

| | 学習 | 推論 |
|---|---|---|
| 計算の量 | 推論の数万倍（全データ×何十周×逆算つき） | 1枚ぶんの流れ作業 |
| メモリ | 全例題＋途中経過を大量に保持 | 重みと作業領域だけ（〜数十KB） |
| 頻度 | モデルを作るとき数回 | 現場で毎回 |
| 適役 | **PC（NNC）** | **Pico（DNNRT）** |

**学習は学校、推論は現場。** 学校（PC）でみっちり鍛えたダイヤル一式を 14KB のファイル（model.nnb）に焼き、現場（Pico）はそれを淡々と実行する。第1章で見た3ステージのワークフローは、学習と推論の性質の違いをそのまま役割分担にしたものだったのです。

ひとつだけ予告。学習には「例題を丸暗記してしまい、初見の問題が解けなくなる」という落とし穴があります（**過学習**）。見抜き方と対策は、実際に学習を回す第6章と、データを作る第7章で扱います。

## 5.4 NNC のレイヤーパレットと対応づけて学ぶ

### 概念とブロックの対応表

この章で学んだ概念は、そのまま NNC の「編集」タブ左側にある部品棚（コンポーネント）のブロック名に対応しています。次章で組むときの辞書として使ってください。

| この章の概念 | NNC のブロック名 | 役割の一言 |
|---|---|---|
| 入力（28×28の画像） | **Input** | データの入り口。サイズをここで宣言 |
| 畳み込み（判子押し） | **Convolution** | パターン検出。フィルタ枚数を設定 |
| マイナスは黙る | **ReLU** | 活性化。Convolution とセットが基本 |
| 縮めて鈍感に | **MaxPooling** | 2×2 で縮小が定番 |
| 全結合（総合判定） | **Affine** | 最終判定の裁判所 |
| 点数→確率 | **Softmax** | 出力の仕上げ |
| ③ 正解と比べる | **CategoricalCrossEntropy** | 学習時だけ使う「採点係」 |

最後の CategoricalCrossEntropy だけ、この章で説明していない新顔です。これは 5.3 の学習ループの「③正解と比べて間違いの大きさを測る」を担当する**採点係**で、**学習のときだけ必要**なブロックです。ここに、後で効いてくる大事な区別があります。

```text
   NNC 上のネットワーク:
   Input → Convolution → … → Softmax → CategoricalCrossEntropy
   └────────── Pico に持っていく部分 ──────────┘   └─ 学校に置いていく ─┘
```

第8章で model.nnb に変換するとき、持っていくのは Softmax まで。採点係は現場には要らないからです。「**採点係は学校に置いていく**」と覚えておくと、第8章で迷いません。

### ブロックの「自由」と DNNRT の「現実」

NNC のパレットには、この表以外にも何十種類ものブロックが並んでいます。BatchNormalization、Dropout、LSTM… 眺めるだけで楽しい棚ですが、本書では冒険しません。理由は第9章で詳しく述べますが、一言でいえば **Pico 側の DNNRT が実行できるブロックには限りがある**ためです（対応表は付録C）。本章で挙げた6種＋採点係は、いずれも確実に動く「鉄板の部品」です。まずはこの部品だけで、実用になるカメラが作れることをこの本全体で証明していきます。
