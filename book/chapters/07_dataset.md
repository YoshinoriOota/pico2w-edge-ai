# 第7章 自分のデータセットを作る — エッジAIの主役はデータ

前章で学習の一巡を体験しましたが、使ったのは Fashion-MNIST という借り物のデータでした。この章では、Pico とカメラを**撮影専用機**に仕立てて、あなたの設置環境だけのオリジナルデータセットを作ります。

先に本章でいちばん大事な一文を書いてしまいます。

> **エッジAIの精度は、モデルの設計よりもデータの質で決まる。**

第5〜6章でモデルの仕組みを学んだ直後にこう言うのは意地悪に聞こえますが、実務のエッジAI開発者なら全員がうなずくはずです。そしてデータの質は、撮り方の工夫 — つまりこの章の内容で決まります。

## 7.1 Pico を「撮影専用機」にする — 収集ツールの製作

### 構成 — 第2章の伏線を回収する

データ収集の構成はシンプルです。Pico 側に小さな「撮影サーバ」を置き、PC 側のツールがシリアル越しに注文を出します。

```text
   PC (collect_tool.py)                Pico (main.py = pico_collect.py)
  ┌─────────────────────┐             ┌────────────────────────────┐
  │ "SNAP" と注文を送る    │ ──USB──→  │ カメラで1枚撮影              │
  │ 38,400バイト受信       │ ←──────  │ "FRAME 38400" + 生データ     │
  │ 28×28に前処理してPNG保存│             │                            │
  └─────────────────────┘             └────────────────────────────┘
```

Pico 側のスクリプト（サポートリポジトリ `code/collect/pico_collect.py`）は、第4章のドライバで撮影し、`PING`（生存確認）、`SNAP`（撮影して送信）、`QUIT`（終了）の3つの注文に応えるだけの、30行ほどのプログラムです。

これを Pico に **`main.py` という名前で保存**してください。第2章の最後で「main.py は電源投入で自動実行される」と学んだのを覚えていますか。あの性質をここで使います。PC 側ツールは接続時に Pico をソフトリセットし、main.py（＝撮影サーバ）が自動起動して `READY` と挨拶してくる — という段取りです。第2章で転送済みの `ov7670.py` も必要です（配線は第4章のまま）。

```sh
# Pico への配置 (mpremote 派の例。Thonny の「デバイスに保存」でも同じ)
mpremote cp code/ov7670_pio/ov7670.py :ov7670.py
mpremote cp code/collect/pico_collect.py :main.py
```

**注意がひとつ。** PC 側ツールを動かす間は **Thonny を閉じてください**。シリアルポートは同時に1つのプログラムしか使えないため、Thonny がつないだままだとツールが「ポートが開けない」と怒られます。この「ポートの取り合い」はシリアル通信の定番トラブルなので、体で覚えておくと得です。

### PC 側ツール — 対話モードと自動モード

PC 側（`code/collect/collect_tool.py`）は Python スクリプトです。第4章で PC に Python を入れていれば、追加は2つのライブラリだけ：

```sh
pip install pyserial pillow
```

使い方は2モードあります。まず**対話モード** — Enter キーを押すたびに1枚撮って保存します。

```sh
python collect_tool.py --port /dev/ttyACM0 --out dataset --class-name box
# Windows なら --port COM5 のように

接続OK: /dev/ttyACM0
Enter=撮影 / 文字列=クラス切替 / q=終了  (現在: box)
[box] >            ← Enter で撮影
保存: dataset/box/box_0000.png
[box] > empty      ← クラス名を打つと切替
クラスを切り替えました: empty
[empty] >
```

そして本命の**自動モード** — 定点カメラらしく、一定間隔で黙々と撮り続けます。

```sh
# 「荷物なし」を5秒間隔で100枚
python collect_tool.py --port /dev/ttyACM0 --out dataset \
    --class-name empty --auto 100 --interval 5
```

筆者の検証では、撮影から保存までは1枚あたり約1秒。100枚の収集は放置で10分ほどです。`--save-full` を付けると、確認用の 160×120 カラー画像も `_full/` フォルダに残ります（何が写っていたか後で見返せるので、最初のうちは付けておくのがおすすめです）。

### 保存される画像が「28×28 グレースケール」である理由

ツールが保存するのは、160×120 のカラー画像**ではなく**、そこから作った **28×28 のグレースケール画像**です。縮小の手順は「中央 112×112 を切り出し、4画素おきに間引き、グレースケール化」— 実はこれ、**第9章で Pico が推論の直前に行う前処理と、1画素単位で同一のロジック**です。

なぜ揃えるのか。学習時と推論時で前処理が少しでも違うと — 切り出し位置が数画素ずれる、グレースケール化の係数が違う、明るさの正規化が違う — モデルは「学習で見ていた世界と違う世界」を見せられることになり、精度は静かに、しかし確実に崩れます。しかも**エラーは一切出ない**ので、原因究明は困難を極めます。

本書はこの事故を、**収集ツールと推論コードが同じ前処理ロジックを使う**という構造で防ぎます。「前処理は学習と推論で揃える」— 本章の鉄則その1です。

## 7.2 題材は設置型を意識する — 何を撮るか

### 混同行列の教訓を、題材選びに使う

第6章の混同行列で「上半身の服同士は紛れる、ズボンは紛れない」を見ました。あの教訓の実践編がここです。**分類しやすい題材を選ぶこと自体が、最強の精度改善**なのです。本書がすすめる題材の条件は3つ：

- **定点であること。** カメラは固定し、背景は毎回同じ。モデルは「変化した部分」にだけ集中できます
- **2〜3クラスで始めること。** 10クラスの Fashion-MNIST より、あなたの2クラスの方がずっと簡単です
- **クラス間でシルエットが大きく違うこと。** 「ある/ない」は最強の組み合わせです — 画面の一角が箱で埋まるか、床が見えるか。ズボン級に見分けやすい問題設定です

この条件を満たす実用的な題材の例：

| 題材 | クラス | 用途 |
|---|---|---|
| 置き配検知（本書の主役） | 荷物あり / なし | 第11章プロジェクト1 |
| 在席検知 | 人がいる / いない | 会議室・自席の見える化 |
| 駐車場チェック | 車がある / ない | 帰宅前の空き確認 |
| ペットの皿 | 餌が残っている / 空 | 餌やりリマインド |

逆に、初挑戦で避けたいのは「箱の荷物とポリ袋の荷物を区別」「猫と犬を区別」のような**シルエットの似たものの分類**です。できないわけではありませんが、必要なデータ量も難易度も跳ね上がります。まず「ある/ない」で全パイプラインを完走させ、それから難しい問題に挑む — この順番を強くおすすめします。

### 「なし」クラスをなめてはいけない

初心者が必ず踏む落とし穴をひとつ。「荷物あり」の写真は熱心に集めるのに、「荷物なし」は数枚で済ませてしまうケースです。

モデルにとって「なし」クラスは「あり以外のすべての世界」を背負う重要なクラスです。朝の斜光の玄関、曇りの日の玄関、夕方の影が伸びた玄関、落ち葉が転がった玄関 — これらが全部「なし」に見えるように学習させなければ、「夕方になると誤検知するカメラ」が出来上がります。**クラスの枚数は同じくらいに、バリエーションは「なし」側にこそ厚く。** 鉄則その2です。

## 7.3 NNC のデータセット形式（CSV＋画像フォルダ）への整形と登録

### フォルダ構成と CSV の生成

収集を終えると、フォルダはこうなっているはずです。

```text
  dataset/
  ├── empty/   empty_0000.png, empty_0001.png, ...   (28×28 グレー)
  ├── box/     box_0000.png,  box_0001.png,  ...
  └── _full/   (確認用カラー。学習には使わない)
```

NNC がデータセットとして受け付けるのは「画像一覧の CSV」です。形式は第6章のデータセット画面で見たとおり、1列目 `x:image` に画像パス、2列目 `y:label` にクラス番号。これを手で書くのは苦行なので、生成スクリプト（`code/collect/make_nnc_dataset.py`）を用意しました。

```sh
python make_nnc_dataset.py dataset

クラス番号の割り当て (フォルダ名昇順):
  0: box            120枚
  1: empty          135枚
生成: dataset/nnc_training.csv (204行)
生成: dataset/nnc_validation.csv (51行)
```

スクリプトは全画像をシャッフルし、**80% を学習用、20% を評価用**に分けて2つの CSV を作ります。第6章で「初見データでの成績が本当の実力」と学びました — その「初見データ」を最初から取り分けておくわけです。

2点だけ仕様を覚えてください。**クラス番号はフォルダ名の昇順**で決まります（box=0、empty=1。後で Pico の推論結果を解釈するときに必要な対応表です）。そして**シャッフルは乱数シード固定**なので、何度実行しても同じ分割になります（実験の再現性のためです）。

### NNC への登録

生成した CSV を Windows 機へ持ち込みます。`dataset` フォルダごとコピーしてください（CSV 内のパスは相対パスなので、フォルダごと動かせばどこに置いても壊れません）。

NNC での登録は、ホーム画面左の**データセット** → 「データセットを開く」から `nnc_training.csv` と `nnc_validation.csv` をそれぞれ開くだけです。第6章で見た Fashion-MNIST と同じ画面に、今度は**あなたの玄関先**がサムネイルで並びます — ちょっと感動する瞬間なので、ぜひ味わってください。

プロジェクトへの割り当ても第6章と同じです（データセット画面で Training / Validation にそれぞれ指定）。ひとつだけ確認を：**「Image Normalization (1.0/255.0)」のチェックが入っていること**。第9章の Pico 側前処理は「画素値 ÷255」を前提にします。ここが揃っていないと、鉄則その1が崩れます。

## 7.4 データ拡張と「設置環境そのもので撮る」鉄則

### なぜ Web の画像ではだめなのか

「荷物の画像なんて、ネットに山ほどあるのでは？」— もっともな疑問です。しかし Web から集めた美しい宅配箱の写真で学習させたモデルは、あなたの玄関ではほぼ確実に働きません。

理由は、モデルが画像の「内容」だけでなく**「写り方」まで丸ごと学習する**からです。あなたのカメラの解像度とノイズ、レンズの歪み、設置角度、玄関の照明、背景のタイル模様 — これらすべてが込みで「あなたの環境の荷物」です。Web の写真とは、写り方の分布がまるで違います。

だから鉄則その3は、**本番と同じカメラ・同じ位置・同じ画角で撮る**。理想を言えば、収集時のカメラ設置をそのまま動かさずに運用へ移行することです。第6章の Fashion-MNIST で高精度が出たのは、学習画像と評価画像が「同じ写り方」だったから — あなたの環境でも同じ条件を自分の手で作るのです。

### 何枚集めるか、いつ撮るか

目安を示します。「ある/ない」の定点2クラスなら、**各クラス 100〜300枚**で実用ラインに届きます（Fashion-MNIST の6万枚と比べて途方もなく少ないのは、定点・2クラス・同一環境という好条件のおかげです)。

枚数より効くのが**撮影時間帯の分散**です。自動モードの出番はここです：

```sh
# 朝・昼・夕・夜、それぞれの時間帯で25枚ずつ = 「なし」100枚
python collect_tool.py --port /dev/ttyACM0 --out dataset \
    --class-name empty --auto 25 --interval 30
```

「あり」クラスは荷物の置き位置・向き・種類を変えながら対話モードで。段ボール箱だけでなく、封筒、紙袋など、実際に届きうるものを混ぜてください。

ありがちな失敗がひとつ。「あり」を昼だけ、「なし」を夜だけに撮ると、モデルは荷物ではなく**明るさで判定するズル**を覚えます（学習データに潜んだ手がかりの「漏れ」です）。学習曲線も評価も好成績なのに実運用で全滅する、たちの悪いパターン — 両クラスとも時間帯を混ぜることで防げます。鉄則その4です。

### データ拡張 — 撮った枚数を水増しする

集めた画像に小さな変換（ずらす、回す、明るさを変える）を加えて教材を水増しする技を**データ拡張（Data Augmentation）**と呼びます。NNC ではコンポーネント棚の **ImageAugmentation** レイヤーを Input の直後に置くだけで、学習のたびに毎回少しずつ違う画像として見せてくれます（推論時には自動で素通しになります。つまり Pico 側には持ち込まれません — 安心してください）。

定点カメラの場合、効果的な拡張は控えめです：**わずかな平行移動、わずかな明るさ変化**。カメラは固定なので、大きな回転や反転はかえって「ありえない画像」で学習を汚します。拡張はあくまで補助 — **実写100枚は、拡張で水増しした1000枚に勝る**ことは忘れずに。
