# 第2章 開発環境を整える — 学習の道具と、推論の道具

この章では、本書で使う道具をすべてそろえます。やることは大きく2つ。PC 側に「AI を学習させる道具」（Neural Network Console）を、Pico 側に「AI を実行する道具」（dnnrt 組み込みファームウェアと Thonny）を入れることです。

```text
        PC (Windows)                        Raspberry Pi Pico 2 W
  ┌───────────────────────┐           ┌───────────────────────────┐
  │ Neural Network Console │           │ MicroPython ファームウェア    │
  │  → モデルを設計・学習     │  ......   │ (dnnrt 組み込み・配布版)      │
  │     (2.1〜2.2)         │           │  → モデルを実行 (2.3)        │
  ├───────────────────────┤           └───────────────────────────┘
  │ Thonny                 │                       ↑
  │  → Pico と対話する窓口   │───── USB ─────────────┘
  │     (2.4〜2.5)         │
  └───────────────────────┘
```

章の最後には、Pico の上で `import dnnrt` が通り、L チカが動くところまで確認します。所要時間は、ダウンロード待ちを除けば30分ほどです。

## 2.1 Neural Network Console のセットアップ

### 入手先は GitHub に変わった

Neural Network Console（以下 NNC）は、Sony が無償公開しているディープラーニングの統合開発環境です。かつては専用サイトからのダウンロードとクラウド版の2本立てでしたが、状況が変わっています。

- **クラウド版は 2024年12月25日 にサービスを終了しました。** Web 記事などでクラウド版の画面を見かけても、もう使えません
- **Windows 版は現在も更新が続いており、配布場所は GitHub に移っています。** 本書執筆時点の最新はバージョン 3.50（2025年9月リリース）です

入手手順は次の通りです。

1. ブラウザで `https://github.com/sony/neural-network-console/releases` を開く
2. 最新リリース（Latest の表示があるもの）の Assets からアーカイブをダウンロードする
3. ダウンロードしたファイルを展開（解凍）する

**インストーラはありません。** 展開したフォルダの中の `neural_network_console.exe` を直接ダブルクリックして起動する方式です。レジストリを汚さないぶん、アンインストールもフォルダ削除だけで済みます。

展開先について、昔からの定番の注意をひとつ。**フォルダのパスに日本語やスペースを含めない**ことです。`C:\Users\山田 太郎\デスクトップ\` のような場所に置くと、学習時に原因のわかりにくいエラーが出ることがあります。`C:\nnc\` のような浅くて素直な場所をおすすめします。

### 動作要件 — ふつうのノート PC で足ります

NNC は Windows 10/11（64bit）で動作します。そして第1章で予告した通り、**GPU は不要です**。

ディープラーニングに GPU が必須と言われるのは、大きなモデルを大きなデータで学習させる場合の話です。本書が扱うのは 28×28 ピクセルの画像を数百枚〜数千枚学習させる世界で、この規模なら CPU だけで数分あれば終わります。メモリは 8GB あれば十分です。

### Windows 機がない読者へ

NNC は Windows 専用のため、Mac や Linux しかない場合は選択肢が絞られます。正直に整理すると：

- **一番現実的なのは、家庭や職場の Windows 機を「学習のときだけ」借りることです。** 本書のワークフローで Windows が必要なのは学習と変換（第6〜8章）だけで、それも1回あたり数十分です。Pico とのやり取り（本書の大半の時間）は Mac でも Linux でもできます
- プログラミングに抵抗がなければ、NNC の中身であるライブラリ nnabla（Python 版）は Mac/Linux でも動きます。ただし GUI の恩恵は受けられません。この道は第12章「次の一歩」で紹介します

### 起動確認

`neural_network_console.exe` を起動し、初回のセットアップ（利用規約への同意など）を済ませると、プロジェクト一覧の画面が開きます。ここにはあらかじめ多数のサンプルプロジェクトが並んでいます — この時点では眺めるだけで OK です。ひとつでも画面が開けば、インストールは成功しています。

## 2.2 NNC の画面構成ツアー

本格的に使うのは第6章からですが、地図を先に頭に入れておくと後の章の見通しがよくなります。NNC の作業画面は、上部のタブで切り替える構成になっています。ここでは本書で使う3つのタブだけ覚えてください。

なお、Web の解説記事では旧バージョンの英語表記（EDIT / TRAINING / EVALUATION）が出てくることがありますが、現行版の UI は日本語です。読み替えてください。

### 「編集」タブ — ネットワークを「組み立てる」場所

画面の左側に **コンポーネント**（Convolution、MaxPooling、Affine といった部品の一覧棚）、中央に **キャンバス** があります。棚から部品をドラッグしてキャンバスに置き、上から下へつなげていくと、それがそのままニューラルネットワークの設計図になります。

プログラミング経験者は「コードを書かずに大丈夫なのか」と不安になるかもしれませんが、心配は逆です。ネットワーク構造は本来グラフ（図）であり、図を図のまま編集できるのはむしろ自然な形です。ブロックの意味は第5章で、実際の組み立ては第6章でやります。

### 「学習」タブ — 学習を「見守る」場所

学習を開始すると、このタブに **学習曲線（Learning Curve）** がリアルタイムで描かれていきます。横軸が学習の進み（エポック）、縦軸が誤差です。曲線がすっと下がっていけば学習は順調、下がらなければどこかに問題があります。グラフの読み方 — どこで学習を止めるべきか、過学習をどう見抜くか — は第6章で扱います。

### 「評価」タブ — 結果を「検分する」場所

学習が終わったら、モデルに初見のデータ（評価データ）を解かせて成績を見るのがこのタブです。正解率（Accuracy）のほか、**混同行列**（どのクラスをどのクラスと間違えたかの一覧表）や、1枚ごとの判定結果を確認できます。本書で特に重要なのは、第9章で Pico 実機の推論結果とこのタブの結果を突き合わせる場面です。**PC と Pico で同じ入力から同じ答えが出ること** — これがエッジAI移植の品質保証になります。

画面右上にはタブと並んで **データセット**（データの登録・確認。第7章で使用）と **コンフィグ**（学習回数などの設定。第6章で使用）のボタンがありますが、出てきたときに説明します。

## 2.3 Pico 2 W にファームウェアを書き込む

### 標準の MicroPython では足りない

Pico 側の準備は、MicroPython ファームウェアの書き込みから始まります。ただし micropython.org で配布されている標準ファームウェアではなく、**本書の配布ファームウェア**を使ってください。

理由は単純で、標準ファームウェアには推論エンジン DNNRT が入っていないからです。DNNRT は C 言語で書かれたモジュールなので、後から Python ファイルのように追加することができず、ファームウェアに焼き込んでおく必要があります。本書の配布ファームウェアは「標準 MicroPython + `dnnrt` モジュール」という構成で、標準版にあるものはすべてそのまま使えます。

ファームウェアは本書のサポートリポジトリから入手します：

```text
（サポートリポジトリ）/code/dnnrt_upy/firmware/firmware.uf2
```

自分でソースからビルドしたい人のための手順は付録 F にあります（C コンパイラが必要になりますが、一度きりの作業です）。

### BOOTSEL ボタンで書き込む

Pico へのファームウェア書き込みは、専用ツール不要の「ドラッグ&ドロップ方式」です。

1. Pico 2 W の USB ケーブルをいったん抜く
2. 基板上の **BOOTSEL ボタンを押しながら** USB ケーブルを PC につなぐ
3. ボタンを離す。PC に USB メモリのようなドライブ（`RP2350` という名前）が現れる
4. そのドライブに `firmware.uf2` をコピーする
5. コピーが終わると Pico が自動的に再起動し、ドライブ表示が消える

これで書き込み完了です。以後、普通に USB をつなげば MicroPython が起動します（BOOTSEL は書き込みのときだけ使います）。

うまくいかないときの定番は2つ。**ドライブが現れない**場合は、USB ケーブルが充電専用でないか確認してください（データ線のないケーブルが世の中には結構あります）。**`RP2350` ではなく `RPI-RP2` と表示される**場合は、手にしているのが旧型の Pico（W）です。第1章の部品表どおり Pico **2** W かどうか、基板のシルク印刷を確認してください。

## 2.4 Thonny と最初の対話

### Thonny のインストールと接続

Thonny（トニー）は、MicroPython 開発でもっとも広く使われている無料エディタです。`https://thonny.org` から OS に合ったものをインストールしてください（Windows / Mac / Linux すべてあります）。

起動したら、Pico とつなぐ設定をします。

1. Pico 2 W を USB で接続する
2. Thonny の右下（バージョンによっては「実行」メニュー →「インタプリタ設定」）をクリック
3. インタプリタとして **MicroPython (RP2040/RP2)** 系を選ぶ
4. ポートは通常「自動検出」で見つかります

接続に成功すると、画面下部の **シェル** に `>>>` というプロンプトが表示されます。

Linux ユーザーへの注意をひとつ。ポートが見えているのに接続できない場合、シリアルポートの権限不足が典型原因です。ターミナルで `sudo usermod -aG dialout $USER` を実行し、一度ログインし直してください（筆者もこの本の検証中、最初にここで転びました）。

### `>>>` は Pico との会話窓口

この `>>>` は **REPL**（レプル）と呼ばれる対話画面で、打ち込んだ Python コードを **Pico がその場で実行して** 答えを返してきます。PC 上の Python ではなく、USB の先のマイコンが計算していることに注意してください。試しに：

```python
>>> 1 + 1
2
>>> import sys
>>> sys.implementation.name
'micropython'
```

### 環境構築の総仕上げ — `import dnnrt`

それでは、この章のハイライトです。次の2行を打ってください。

```python
>>> import dnnrt
>>> dnnrt.nnabla_version()
'1.24.0.dev1'
```

エラーなくバージョン文字列が返ってきたら — おめでとうございます。**あなたの Pico には、いま AI 推論エンジンが載っています。** `ImportError: no module named 'dnnrt'` が出た場合は、標準ファームウェアが入っています。2.3 に戻って配布ファームウェアを書き込み直してください。

まだモデルがないので推論はできませんが、環境構築としてはこれで8割終わりました。残りの2割（カメラ）は第4章のお楽しみです。

## 2.5 L チカと REPL の使い方

### まばたきをさせる

マイコン界の "Hello, World" である L チカ（LED 点滅）をやっておきましょう。REPL に次を打ち込みます。

```python
>>> from machine import Pin
>>> led = Pin("LED", Pin.OUT)
>>> led.on()    # 点灯した?
>>> led.off()   # 消えた?
```

基板上の緑の LED が指示どおりに点いたり消えたりするはずです。ピン番号ではなく `"LED"` という名前で指定しているのには Pico 2 W ならではの事情があるのですが、それは第3章で説明します。

点滅を続けるループも書いてみます。

```python
>>> import time
>>> while True:
...     led.toggle()
...     time.sleep(0.5)
...
```

LED が0.5秒ごとにまばたきを始めます。この無限ループを止めるには **Ctrl+C** — REPL の必須操作その1です。実行中のプログラムを中断して `>>>` に戻ります。その2は **Ctrl+D**（ソフトリセット）。Pico を再起動して、まっさらな状態からやり直します。この2つはこの先ずっと使うので、いま指に覚えさせてください。

### ファイルとして保存する — main.py の特別ルール

REPL に打ったコードは、Pico の電源を抜くと消えます。残したいコードは、Thonny のエディタ部分に書いてファイルとして保存します。保存時に「このコンピュータ」か「MicroPython デバイス」かを聞かれるので、**MicroPython デバイス**を選ぶと Pico 内蔵のフラッシュメモリに書き込まれます。

ここで、ひとつだけ特別なファイル名を覚えてください。**`main.py` という名前で保存したファイルは、Pico の電源が入ると自動的に実行されます。** PC につながっていなくても、です。

試しに、さっきの L チカを `main.py` として Pico に保存し、USB を抜いてモバイルバッテリーにつないでみてください。PC がなくても LED がまばたきを続けます — これがマイコンの「自立」の第一歩です。本書の最終形、電池で動く AI カメラも、正体はこの `main.py` の中に「起きて、撮って、考えて、眠る」一連の動作を書き込んだものにすぎません（第10章）。
