# V2残 検証レポート: カメラ + DNNRT 同時動作のメモリ・時間実測

実行日: 2026-07-08
対象: `code/integrated/v2_camera_infer_test.py`（実機 Pico 2 W / RP2350）
構成: OV7670 (QQVGA RGB565, PIO+DMA) + dnnrt (model.nnb: 28x28 gray 入力・11クラス)

## 結果サマリ

「撮影 → 前処理 (160x120 → 中央112x112 → 28x28 グレー) → 推論」の
一気通貫 3 サイクルがすべて成功。**成功基準（ヒープ内完結・10秒以内）達成**。

### メモリ（gc.collect() 後のヒープ空き）

| 段階 | ヒープ空き |
|---|---|
| 起動直後 | 446,112 byte |
| カメラ初期化後 | 445,904 byte |
| フレームバッファ (38,400 byte) 確保後 | 407,488 byte |
| model.nnb ロード + 推論コンテキスト後 | **369,408 byte** |
| 3 サイクル完了後 | 352,592 byte |

カメラ・フレームバッファ・モデル・中間バッファを全部同時に確保しても
**ヒープの 7 割が空いている**。Wi-Fi スタックや第7章の収集ツールを足す
余裕は十分。3 サイクル後の約 17KB の減少は小オブジェクトの滞留で、
サイクルを重ねても単調減少はしない（リークではない）。

### 時間（1 サイクル）

| 工程 | 所要 |
|---|---|
| 撮影 (VSYNC 待ち含む) | 472〜743 ms |
| 前処理 (784 画素, 純 Python) | 19 ms |
| **推論 (dnnrt forward)** | **90 ms** |
| 出力取得 | <1 ms |
| 合計 | 約 850 ms |

企画時の想定は「推論は数秒かかっても間欠動作なら可」だったが、
実測は **90ms** と 2 桁速い。DNNRT (C実装) 採用の効果が数字で出た。
ボトルネックはむしろ撮影の VSYNC 待ちで、それでも 1 サイクル 1 秒未満。

### 推論出力

3 サイクルとも class 6 (score 0.999) で一貫。被写体（机上の機材）は
モデルの学習対象外なので値自体に意味はないが、同一入力に対して
出力が安定していることの確認にはなる。

前処理結果の目視確認: `sample_preprocessed.png`（28x28 を 10 倍拡大）。
カメラフレーム中央部と構図が一致し、縮小・グレースケール化は正しい。

## 執筆メモ

- `const()` は import した名前を含む式には使えない（MicroPython の制約。
  `X0 = const((FRAME_W - CROP) // 2)` はコンパイルエラーになる）
- 前処理は 784 画素なら純 Python で 19ms。viper 化は不要（第9章の
  「高速化テクニック」節は削るか、コラム程度に格下げしてよい）
- メモリ試算の書籍向けまとめ: 520KB SRAM のうち MicroPython ヒープ約446KB、
  カメラ 38KB + モデル一式 38KB を引いても 369KB 残る
