# V3 検証レポート: 消費電流実測と電池寿命試算

実行日: 2026-07-08
対象: Pico 2 W + OV7670 + DNNRT 構成（`code/integrated/v3_states.py` で各状態を保持）
計測: USB 給電経路に電流計を直列挿入し目視読み取り（µA 分解能）。
      **USB 接続状態での測定値**であり、電池駆動時の真値に対しては上限側の目安。

## 電池寿命試算（成功基準の判定）

条件: 単3×2本 = 2000mAh、撮影間隔 10 分、1 サイクル =
起動→撮影→推論（約2秒 @30.5mA）→ Wi-Fi 通知（約6秒 @42mA）→ deepsleep（残り時間）

```
1サイクル(600s)の消費 ≈ 2×30.5 + 6×42 + 592×6.0 ≈ 3865 mA·s
平均電流 ≈ 6.4 mA
稼働時間 ≈ 2000mAh / 6.4mA ≈ 310時間 ≈ 13日
```

**成功基準「撮影間隔10分・単3×2本で1週間以上」→ 達成（試算 約13日）** ✅
lightsleep 運用（10.1mA）でも平均 約10.5mA → 約7.9日でぎりぎり達成。
deepsleep 前提なら余裕を持って成立する。

USB 接続込みの上限値でこの結果なので、電池直結の実運用ではさらに伸びる方向。
精密値（電池駆動・テスター計測）は執筆時に付録 E 用として再測定する。

## 検証中の発見（書籍ネタ）

### 1. CYW43（Wi-Fi チップ）の消し忘れは lightsleep を帳消しにする

Wi-Fi 使用後にソフトリセットしただけでは CYW43 が電力を食い続け、
lightsleep 中でも 29.2mA（アイドルより高い）だった。
`wlan.active(False)` + `wlan.deinit()` を明示すると 10.1mA まで低下。
**「Wi-Fi は送るときだけ、使い終わったら明示的に切る」**（第10章の核心）。

### 2. rp2 ポートの deepsleep は「復帰＝リセット」

`machine.deepsleep(ms)` からの復帰はリセット動作となり main.py が再実行される。
つまり「main.py に間欠動作サイクルを書く」という本書第10章の設計と
自然に一致する。deepsleep 復帰時は USB も再列挙される（PC から見ると
接続し直しに見える）点はデバッグ時の注意。

### 3. deepsleep でも 6mA 止まり（MicroPython の制約）

RP2350 のハードウェアとしては dormant モード（µA オーダー）があるが、
MicroPython の `machine.deepsleep` では 6mA 止まり。
それ以上を狙うなら TPL5110 等の外部タイマー IC による電源断方式
（6mA → 数十µA、単3×2本で数ヶ月級）。第10章末の「さらに攻める」節の
価値が数字で裏付けられた。

### 4. 測定手順上の注意

- lightsleep/deepsleep 中はシリアル応答がなくなるため、スリープ系の測定は
  シリアル通信に依存しない自律スクリプト（main.py サイクル）で行うのが確実
- 本検証中に一度 USB CDC が無応答になったが、接触不良のあるケーブルが
  原因だった可能性が高い（安定ケーブルでは再現せず）
- Linux ではシリアルポート権限に dialout グループが必要。再ログイン前でも
  `sg dialout -c "mpremote ..."` で回避できる
