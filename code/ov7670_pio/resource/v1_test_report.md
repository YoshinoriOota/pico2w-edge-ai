## 検証中に発見・修正した問題（書籍のハマりどころ候補）

### 1. RP2350 では Pin を入力初期化しないと PIO から信号が見えない

初回実行時、V1-5 が capture timeout で失敗。原因は PCLK/HREF/D1-D7 の
パッド入力イネーブルが立っておらず、PIO の `wait(gpio)` が永遠に待っていたこと。
`Pin(n, Pin.IN)` を PIO が参照する全ピン（D0-D7・PCLK・HREF・VSYNC）に対して
明示的に行うことで解決。VSYNC だけは当初から Pin 初期化していたため
V1-3（CPU からのエッジ観測）は通っており、切り分けの手がかりになった。

### 2. COM10 の PCLK ゲーティングだけでは行のバイトずれが発生する

初版の PIO プログラム（6 命令、PCLK 立ち上がりで無条件取り込み）では、
取得画像に「1 行ごとのマゼンタ/緑の縞」と「斜めのシアー」が発生した。
1 行あたりの取り込みバイト数が 320 からずれ、RGB565 の上位/下位バイトの
位相が行ごとに反転していたことが原因（ブランキング境界の余分な PCLK
エッジを拾っていたと推定）。

対策として PIO プログラムを **HREF 同期方式**に変更:
行ごとに HREF 立ち上がりで再同期し、X レジスタで 1 行きっかり 320 byte を
カウントして取り込む（1 行のバイト数-1 はホストが TX FIFO 経由で渡す）。
命令数は 11 命令（32 命令制限に対して依然余裕）。変更後、縞・シアーとも
完全に解消した。
